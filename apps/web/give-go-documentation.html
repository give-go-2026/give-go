4. Server vs. Client komponensek

A Next.js App Routerben minden komponens alapértelmezés szerint Server Component. Client oldali funkcionalitás (hook-ok, event handler-ek, böngésző API-k) csak Client Component-ben lehetséges.

JellemzőServer ComponentClient Component
Fájl elejénsemmi'use client'
React hook-okNemIgen (useState, useEffect, stb.)
Event handler-ekNemIgen (onClick, onChange, stb.)
Adatbázis hozzáférésIgen (közvetlenül)Nem (API-n keresztül)
Navigációredirect() from next/navigationuseRouter() from next/navigation
Link komponens<Link href="..."> from next/link<Link href="..."> from next/link
Képek<Image> from next/image<Image> from next/image
localStorageNemIgen
Ökölszabály: Ha egy komponensnek van useState, useEffect, onClick stb. — kell a 'use client'. Ha csak megjelenít adatot (props-ból vagy adatbázisból), maradhat server component.

Navigáció szerver vs. kliens oldalon

// Server component – programmatikus átirányítás
import { redirect, notFound } from 'next/navigation'

if (!card) notFound()        // 404 oldalt jelenít meg
redirect('/coming-soon')     // HTTP 307 átirányítás

// Client component – felhasználói interakcióra
'use client'
import { useRouter } from 'next/navigation'

const router = useRouter()
router.push('/create')       // programmatikus navigáció
router.back()                // visszalépés

7.4 Új API / adatbázis hívás hozzáadása

Adatbázis műveletek Server Action-ként vagy közvetlenül server componentben végzendők. Kliens oldali fetch csak külső API-khoz indokolt.

// Server Action (features/valami/lib/actions.ts)
'use server'

import { db } from '@/database'
import { events } from '@/database/schema'
import { eq } from 'drizzle-orm'

export async function getEventById(id: number) {
  const result = await db
    .select()
    .from(events)
    .where(eq(events.id, id))
    .limit(1)
  return result[0] ?? null
}

// Server component-ben hívás
const event = await getEventById(Number(id))
if (!event) notFound()

8.3 Validáció (forms.tsx)

A forms.tsx tartalmaz minden validációs logikát Zod sémákkal. Az eredmény Record<string, string> (field neve → hibaüzenet), amit le kell adni a form komponenseknek prop-ként.

FüggvényValidált mezők
validateFirst() orgName, userName, userEmail (email formátum), userPhone (min 7 kar.), orgWeb, password (min 8 kar.), orgNum, logo (fájl megléte)
validateSecond() eventName, eventAddress, majd helpFrequency értékétől függően:
Egyszeri: eventStartDate, eventStartTime, eventEndTime, eventEndDate, eventCloseTime
Rendszeres: seriesStartDate, seriesEndDate + legalább 1 nap kiválasztva + startTime/endTime (vagy naponkénti időpontok)
validateThird() desc (min 1, max 1000 kar.), eventImages (legalább 1 kép)

Hiba megjelenítés

  • 1–2. lépés: fieldErrors Record → minden field az error prop-ján kapja meg a saját hibáját, közvetlenül a mező alatt jelenik meg
  • 3. lépés beküldésekor: mind a 3 lépés validálódik egyszerre — a 3. lépés hibái inline, az 1–2. lépés hibái [Szervezet adatai] / [Esemény adatai] prefix-szel összefoglalóként
  • Vissza gombra a hibák törlődnek
  • Sikeres beküldés után: router.push('/create/success')
localStorage kulcsok: helpFrequency, helpMode, selectedDays (JSON tömb), differentTimes (string "true"/"false") — ezeket a forms.tsx validáció közvetlenül olvassa. A form-two.tsx ezeket useEffect-tel szinkronizálja.
